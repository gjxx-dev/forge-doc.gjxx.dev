# 版本管理

在模组开发中，清晰且可预测的版本策略非常重要，尤其在处理依赖与更新检查时。Forge 文档使用与 Maven 相同的版本范围语法，用于 `mods.toml` 中的 `loaderVersion` 与依赖的 `versionRange` 字段。

推荐做法
---------

- 使用语义化版本（SemVer）或兼容的扩展格式，例如 `1.0.0.0` 或 `1.21.1-1.0.0.0`。
- 在发布兼容 Minecraft 新版本或修复 bug 时，更新主版本或次版本号以表达更改范围。
- 在 `mods.toml` 中使用 `${file.jarVersion}` 或通过构建过程注入版本号以保持一致性。

版本范围示例
---------

- `[1.0,)` ：版本 >= 1.0
- `[1.0,2.0)` ：1.0 <= 版本 < 2.0
- `[,1.0]` ：版本 <= 1.0

在 `mods.toml` 的 `loaderVersion` 中使用版本范围来表示模组可接受的 Forge Loader 版本。例如 `loaderVersion = "[52,53)"` 表示兼容 52.x，但不包含 53.x。

工具支持
---------

在 Gradle 构建脚本中，你可以使用属性与任务将版本号注入到 `mods.toml`，或在打包时替换 `${file.jarVersion}`。
